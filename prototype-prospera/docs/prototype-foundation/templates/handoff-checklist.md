# Client prototype readiness and delivery checklist

Copy into the client project. Record evidence next to checked items; unchecked items remain open.

## Before implementation

- [ ] Client ID, labels, locale/time zone, data mode and shareable classification supplied.
- [ ] Scope distinguishes included/excluded/deferred/undecided and identifies demo coverage.
- [ ] Solution architecture responsibilities/boundaries provided separately from HTML runtime.
- [ ] Methods confirmed (including APQC spelling if intended) and mapped to actual capabilities/evidence.
- [ ] Source register distinguishes shareable provenance from private records.
- [ ] Entity, relation, flow, metric and workspace IDs supplied; missing data explicit.
- [ ] Views and scenarios enabled only where prerequisites exist.
- [ ] Font/logo assets licensed and approved for embedded distribution, or fallbacks selected.

## Architecture and atomic UI

- [ ] Pack schema and reference validation implemented; unsupported versions rejected.
- [ ] Generic components contain no client identity/business fixture records.
- [ ] PRENTER extraction references a source revision; no runtime font imports.
- [ ] All shared components/variants and prototype extensions cataloged and visually reviewed.
- [ ] No duplicated feature atoms, arbitrary client HTML/code, or visual values outside registered tokens/geometry.
- [ ] Solution, scope and method references resolve; proposed versus confirmed is visible.

## Priority interaction review

- [ ] Web levels/detail/camera remain separate; context Back restores camera/history.
- [ ] Single-click inspector, explicit deep navigation, related links and close/focus work.
- [ ] Objective path and area lens emphasize only declared relationships; clearing/filter recovery works.
- [ ] Branch expansion, long labels, dense maps and readable flows do not overlap.
- [ ] List alternative and keyboard paths cover every primary map operation.
- [ ] Desktop evidence/tool/review journey works; rejection does not apply changes.
- [ ] Chat/terminal share one session; workspace drafts and event routing stay isolated.
- [ ] Simulation label is visible; unsupported input and tool errors are honest.
- [ ] Hidden-tab playback pauses; Stop and Reset cancel queued events; repeated approval does not duplicate patches.

## Artifact delivery

- [ ] Generated HTML opens directly through `file://` with networking disabled and no console errors.
- [ ] All five tabs, inline assets and both previews work; no server/service account required.
- [ ] Artifact has no external asset imports, fetches, filesystem paths, hidden private sources or other-client records.
- [ ] Build manifest/report captures client/version/revision/hash; artifact size reviewed against budget.
- [ ] Rendered review at 1440×900, 1024×768, 390×844 and 200% text zoom completed.
- [ ] Focus, contrast, modal sheet, reduced motion and non-color status checks completed.
- [ ] Required UX acceptance journeys recorded with evidence; no inert action-looking controls.
- [ ] Recipient sees only the single HTML; source pack/catalog/report remain local unless separately requested.
